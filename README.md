# markku - "The Secret Life of Mr. Black" (Orange, 1997)
Port status: **phase 1 done (harness + golden frames); JS port: all 13 scenes are ported and 13 of 13 are bit-exact against the Unicorn oracle over the frames the oracle recorded** (the intro, orders 0-1; fx01 eye warp + title cards, orders 2-3, 334 frames; fx02 green rings, orders 4-5, 201 frames incl. DAC; fx03 particle cloud, orders 6-7, 521 frames; fx04 particle ring, orders 8-9, 502 frames; fx05 blob spiral + pi scroller, orders 10-11, 201 frames; fx06 light-trail flowers, orders 12-14, 750 frames; the static picture of order 15, fx07, matching the golden frame; fx08, orders 16-17, 556 frames; fx09 wire-frame room, orders 18-19, 501 frames; fx10 eye zoom, orders 20-21, 501 frames incl. DAC fade; fx11 starburst, orders 22-23, 334 frames incl. the order-24 DAC fade; fx12 blur-dots, orders 24-25, 795 frames incl. DAC). Scenes 0-12 are all wired into the player.** Credits: code Hoplite, music Dune (KUSI.IT), graphics Der Piipo, animation Frank. Own `.git` in this folder; original files (DEMO.EXE, KUSI.IT, PETTERI) untouched.

Files: DEMO.EXE (MZ stub + PMODE/W 1.20 + uncompressed LE image, Watcom C + hand-written asm), KUSI.IT (Impulse Tracker 2.x module, played by Niklas Beisert's **Indoor Music System v0.6**), PETTERI (1.7 MB container of 23 files: RIX3 pictures, raw 320x200 images, shade tables, an animation; no compression).

What works (see `re/NOTES.md`):
- `re/le.py` loads the LE objects with fixups; `re/emucore.py` + `re/vga.py` + `re/harness.py` run the original under Unicorn (DOS/DPMI/VGA mode 13h + unchained, PIT/IRQ0, virtual clock, checkpoints) with the IMS setup screen answered ("quiet" device).
- `re/petteri.py` unpacks PETTERI into `re/assets/` (+ PNG previews).
- `re/golden/` = native-resolution frames captured from the original (`python3 re/harness.py OUT T0 T1 STEP`).
- The demo is sequenced by the IT **order** (scene changes at orders 2,4,6,8,10,12,15,16,18,20,22,24,25), so seek = pick the order/row and render.

Bit-exact vs approximated: the intro effect (`web/fx/intro.js`) is bit-exact (503 frames, 0 pixel / 0 palette differences, `node re/check_intro.mjs`) given the recorded per-frame inputs (`web/assets/intro_frames.json`, taken from the oracle, not derived); its scroll branch never fires in the oracle (negative time word), so the player feeds a positive word to make the picture animate: that animation is unverified against the original. Scenes 8, 9, 10, 12 are bit-exact given the original's own per-frame time word (`re/check_fx08/09/10/12.mjs`); in the player the time word is derived from the music clock (word = (t - scene start) * 65536, start = the oracle's order-change clock), which is approximate: the real frame times are machine dependent. Scene 12 is a blur feedback, replayed from the scene start (fixed 14.3 ms call spacing, measured on the oracle) so seek = replay; its fade row in order 25 is derived from the time (+-1 call). Scene 10's fade is a pure function of the word. Scenes 2 and 5 (`re/check_fx02.mjs`, `re/check_fx05.mjs`, oracle `re/oracle_s04_10.py`) are bit-exact given the original's own time word and row per call; they are feedback effects replayed from the scene start at a fixed 4682/4680 word spacing (the oracle's mean, real spacing is machine dependent), rows derived from the time at 9/s. Scenes 1, 3, 4, 6 and 11 (`re/check_cloud.mjs`, oracle `re/oracle_gen.py`, `re/NOTES.md`): scene 1 is a pure function of (word, order, row); 3, 4, 6, 11 are feedback buffers replayed from the scene start (scene 6 and 11 with checkpoints every 25 calls); like scenes 2 and 5 they are bit-exact given the original's own time word (and order/row) per call, and in the player the word is derived from the music clock with the oracle's mean call spacing (scenes 6 and 11: the original's word counts *down*), so frame times are approximate. Run: `cd web && python3 -m http.server`; test: `node test-player.mjs`, `node tools/uitest.mjs` (headless Chrome; also checks seek determinism). The golden frames come from an emulation whose timing model is approximate (instruction/port-cost clock, no real-hardware calibration), so *when* inside a scene a frame appears is approximate; the pixels of a frame are produced by the original code. Display: mode 13h 320x200 and the 320x400 intro are shown at 4:3 (pixels are not square); the player needs pause + seek.
